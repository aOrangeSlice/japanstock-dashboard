## 1. 为什么独立搭建而不是加切面

A 股版的 render 与模板和 A 股深度耦合（实测代码位置见 A 股版 `render.py`）：

1. **日期轴硬编码**：用 `sh000001` K 线日期当全局交易日轴；日中假日不同（日本祝日 vs 中国调休），同一天可能一边是交易日一边不是，共用日期选择器会打架。
2. **校验逻辑硬编码申万**：校验打印绑定 pt01801080（电子）/ pt01801150（医药），四步校验脚本基线也是 A 股的。
3. **模块维度不对称**：日股无主力资金流、连板梯队、北向持仓（数据源硬限制），切面要么留白要么写两套渲染分支。
4. **语言一致性**：「内容全部日语」最自然的实现是整页日语，混在中文工作台里观感混乱。
5. **故障隔离**：yfinance 是爬虫库可能断更，不能让它拖垮 A 股工作台的每日更新。

独立 ≠ 从零重写：pipeline / render / template / narrative / check 脚本整套骨架拷贝，只换取数层、砍改三个 A 股特色模块、全量翻译。

## 2. 数据源选型（结论与理由）

### 2.1 为什么不用 westock（A 股版的数据源）

westock 对日股仅支持 `search --market jp`（查代码）和 `quote t7203`（实时快照），**不支持 K 线 / 分钟线 / 板块 / 资金流**；`trade-calendar` 是纯 A 股日历。撑不起时序维度。

### 2.2 主源：yfinance

| 能力 | 说明 |
|---|---|
| 个股日 K | `.T` 后缀（7203.T 丰田、9984.T 软银），多年历史 |
| 指数 | `^N225`（日经 225）、`^TOPX`（东证指数） |
| 日内 | 小时线约 730 天、分钟线约 30 天 → 「前場/後場」模块够用，比 A 股版后端的 1 个月还宽裕 |
| 成本 | 免费、免 key、`pip install yfinance` |

**风险与对策**：

| 风险 | 对策 |
|---|---|
| 非官方爬虫库，雅虎改版即断更 | Stooq 降级通道 + `raw_fetch` 日志表记录连续失败并告警 |
| 429 限流（2024 年后收紧，批量请求是重灾区） | 批量 `yf.download()` 一次多只 + 间隔 1~2 秒 + 指数退避重试；pipeline 本身每日增量只取近 7 天，SQLite 即缓存层，请求量天然很小 |
| 行情延迟约 15~20 分钟 | 工作台是「午间 + 收盘」两档快照，非盘中盯盘，可接受；页面需注明「20 分遅延」 |

### 2.3 降级源：Stooq

- 日股 `.JP` 后缀（`7203.JP`）、指数 `^NKX`；CSV 直出，20 年以上历史。
- ⚠️ 2026 年初起需免费 API key，有每日配额 → 适合降级与历史回填，不做主源。

### 2.4 静态数据：J-Quants 免费版（JPX 官方 API）

| 用途 | 端点 | 说明 |
|---|---|---|
| 个股 → 行业映射（dim_stock） | `/v2/equities/master` | 上市名单含 33 業種代码；静态数据**不受免费版 12 周延迟影响**，拉一次长期复用 |
| 日本交易日历 | `/markets/trading_calendar` | JPX 官方休市历（祝日、年末年始），免费版含 |

⚠️ J-Quants 免费版行情数据延迟 12 周，不能当日更行情源；许可为个人使用，禁止再分发。
⚠️ 将来若付费升级（Light ¥1,650 / Standard ¥3,300 每月），可解锁：全市场日 K 一次调用（真·行业成交额）、TOPIX 及 33 業種指数。架构上为纯数据层换血，见 §4.3。

## 3. 行业维度：TOPIX-17 系列 ETF

### 3.1 方案对比（已定稿）

| 方案 | 成本 | 颗粒度 | 结论 |
|---|---|---|---|
| TOPIX 33 業種指数（官方） | J-Quants Standard ¥3,300/月 | 33 个 | 将来付费升级路径 |
| **TOPIX-17 系列 ETF（1617.T~1633.T）** | ¥0（yfinance） | 17 个 | **Phase 1 采用** |
| 自建聚合（全市场 3,800 只按行业加权） | 429 限流不可行 | 33 个 | 排除 |

17 只 ETF 一览（NEXT FUNDS TOPIX-17 シリーズ，代码与行业的精确对应**动手第一步逐一验证**）：

```
1617.T 食品        1618.T エネルギー資源   1619.T 建設・資材
1620.T 素材・化学  1621.T 医薬品          1622.T 自動車・輸送機
1623.T 鉄鋼・非鉄  1624.T 機械            1625.T 電機・精密
1626.T 情報通信・サービスその他           1627.T 電力・ガス
1628.T 運輸・物流  1629.T 商社・卸売       1630.T 小売
1631.T 銀行        1632.T 金融(除く銀行)   1633.T 不動産
```

### 3.2 为什么 ETF 成交额不能当行业资金流

- 東証プライム日成交额约 3~4 兆円，单行业真实成交数千亿円级；17 只 ETF 每只日成交仅数百万~数千万円，**差 4~5 个数量级**。
- ETF 二级成交额只反映基金本身买卖，机构调仓走一级申赎/场外，行业资金真实进出几乎不经过这些 ETF。
- 结论：拿它顶替「主力净流入」会产生方向性失真。

### 3.3 替代语义：資金注目度（改动最小）

```
資金注目度 = 当日 ETF 成交额 ÷ 过去 20 日 ETF 平均成交额
解读：> 2.0 = 資金が当該業種に明確に集中；方向は騰落率と併読
```

- 数据零新增（ETF 成交额本来就要拉）；`main_net` 列改存 ratio，render 改标签与配色。
- 前端呈现：「主力净流入 ±XX億」→「注目度 2.3x ↑」。语义诚实（交易活跃度异常度），且符合日股投资者看売買代金的习惯。

| 估值快照 / 风格 RS | 手工录入口径同 A 股版（日経平均 PER、TOPIX バリュー/グロース） | 手工 | 小 |

### 4.1 制度差异清单

- **货币**：日元，前端 ¥ 易与人民币混淆 → 统一显示「円」或「億円」。
- **涨跌幅限制**：値幅制限（ストップ高/安）按价位分档，非固定 10%，连板逻辑不可平移。
- **配色**：日本同为赤=上昇 / 緑=下落，沿用现配色。
- **交易时间**：前場 9:00-11:30 / 後場 12:30-15:30（JST）。
- **时区**：本机 UTC+9 与日本同区，调度无需换算（A 股版的跨时区坑不存在）。

### 4.2 表结构

直接沿用 A 股版 schema 骨架（`PRIMARY KEY(date,code)` + UPSERT 幂等、快照表先删当日再插、raw_fetch 取数日志），改动点：

- `dim_industry` → `dim_industry_jp`：17 行，`code`=ETF 代码，增加 `source` 列（etf17 / jquants，为升级预留）
- `fact_industry_daily.main_net` → 改存 `attention_ratio`（資金注目度）
- `fact_north_quarterly` → `fact_foreign_weekly`（投資部門別：週次、部門別 net）
- `fact_limitup_daily` → `fact_stophigh_daily`（或 Phase 1 暂缓）
- 数据库文件：`japanstock.db`

### 4.3 可插拔行业层（升级预留）

行业维度抽象为字典表 + 统一取数接口。将来从 TOPIX-17 ETF 升级到 J-Quants 33 業種指数（Standard 付费）时：只换 dim 表 code 与取数函数，schema / render / 前端零改动。同理，J-Quants Light 可解锁「真·業種別売買代金」（全市场日 K 一次调用按 master 行业聚合，每日 2 次调用）。

### 9.3 Phase 1 探針で判明した事実（設計に反映済み）

| 発見 | 対応 |
|---|---|
| **libcurl が非 ASCII パスの CA を読めない**（`curl: (77)`）→ 全リクエスト失敗し「データ源が死んでいる」ように見える | `jpcommon.ensure_ca()` で証明書を一時ディレクトリ（ASCII）へ複製し `CURL_CA_BUNDLE` を注入 |
| `^TOPX` は Yahoo に**存在しない** | TOPIX は `1306.T`（TOPIX ETF、価格 ≈ TOPIX/10）で代理、ページにも明記 |
| 小時足は **730 日**取得可、5 分足 1 ヶ月、1 分足は不可 | 前場/後場を 2 年分回填（A 股版の「直近 1 ヶ月」制約なし） |
| 一括ダウンロードは 27 銘柄 / 3.8 秒で成功（429 なし） | `BATCH=40`, `SLEEP=1.2` に設定 |
| 業種 ETF 17 本すべて 2 年分の連続データあり | 欠損補完は不要だった |
| `8028.T`（ユニ・チャーム）は誤り → 正しくは **`8113.T`** | `universe_seed.py` 修正、`9613.T`（NTT データ）は Yahoo に無く削除 |

### 9.4 実装中に踏んだ追加の地雷（A 股版に無かったもの）

1. **`start`/`end` では 1 時間足の長期区間が取れない**（22 銘柄で全滅）。
   → `period="730d"` なら一括で通る（実測 17,480 本 / 22 銘柄 / 9.3 秒）。
   逐日取得（488 回・実測 25 分超）から一括取得（1 回 9 秒）へ変更。
2. **`JPY=X`（ドル円）を日内集計に混ぜると週末の行が大量発生**（FX は 24 時間取引で 1 日 24 本、日曜から取引）。
   → 日内集計の対象から除外し、書き込み前に**庫内 `^N225` の営業日カレンダーでガード**。実測 104 の週末日付が混入していたのを 0 に。
3. **タイムゾーン**：銘柄によっては別 TZ のバーが返る → `Asia/Tokyo` に変換してから日付を切る。
4. **SQLite の長トランザクションで `database is locked`**：215 銘柄 × 488 日の `pct_chg` 補完を 1 トランザクションで抱えると書込ロックを数分保持し、並行実行が落ちる → 20 銘柄ごとにコミット。
5. **前場/後場の基準終値は小時足シリーズ自身の前日最終バーを採用**：日足終値と 15:00 バー終値は最大 100 ポイント超ずれる日があり、日足基準だと「前場 × 後場」が日足と厳密に一致しない。小時足基準なら定義上必ず閉じる（範囲先頭日のみ日足にフォールバック）。
6. **`drawName` ← `dwName` のタイポ**：4 段階チェックの「未知コンテナ id 検出」が検出（設計通りに機能）。

### 9.5 既知の制約（正直な口径）

- **資金流は代理指標**：業種の「主力資金流入」は日股に存在しない。本ページは「資金注目度＝売買代金 ÷ 20 日平均」で代替し、金額ではなく**倍率**として提示する。
- **騰落銘柄数はユニバース内（215 銘柄）**：東証全銘柄ベースではない（無料データ源の制約）。ページに明記。
- **売買代金は終値 × 出来高の概算**：約定代金の正確値ではない。
- **個別銘柄は直近 250 営業日のみ**データパックに収録（HTML 肥大化防止）。それ以前の日付では当該パネルは降級表示。
- **価格は約 20 分遅延**（Yahoo Finance 仕様）。
- 一部の日で小時足が欠損し、前場/後場が日足と数十ポイントずれる場合がある（実測：2026-09-28 は 15:00 の 1 本のみ）。

### 9.8 金額表示の適応桁数（2026-10-02 追加）

**課題**：業種 ETF の売買代金は実測 **0.0006 〜 28.67 億円**で大半が 1 億円未満。従来の `fmt(v,0)` では **「0 億円」**（例：1629.T＝0.467 億円、1628.T＝0.018 億円）、`fmt(v,1)` でも「0.0 億円」となり情報が失われていた。

**対応**：フロントに適応型フォーマッタ `amtDigits()` / `fmtAmt()` を追加し、金額表示をすべて `fmtAmt` 経由に統一。

| 金額の絶対値 | 小数桁 | 表示例 |
|---|---|---|
| ≥ 100 億円 | 1 桁 | `4,081.5 億円`（アドバンテスト） |
| ≥ 1 億円 | 2 桁 | `28.67` / `2.74` / `1.47` |
| < 1 億円 | **3 桁** | `0.608` / `0.467` / `0.029` / `0.018` |

- 適用箇所（8 箇所）：売買代金合計 / ヒートマップタイル / 前場・後場の売買代金 / 売買代金ランキング / ドロワー（売買代金・前場・後場）/ ドロワー tooltip / ドロワー構成銘柄テーブル
- `render_jp.py` の金額保持精度を **1 桁 → 3 桁**に引き上げ（`E8, 3`）。これをやらないと 3 桁表示しても下位桁が 0 になる
- 検証スクリプトに回帰防止アサーションを追加：`1 億未満の売買代金が小数 3 桁表示（0.018 億円）` → **20 項全通過**
- 副作用：データパックの金額桁数増により HTML 798.0 KB → **838.1 KB**（+40 KB、許容範囲）
